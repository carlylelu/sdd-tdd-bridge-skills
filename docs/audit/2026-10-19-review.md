# Comprehensive iterative audit — 2026-10-19

## Scope and baseline

Audit and repair the current working tree, including prior accepted uncommitted reliability repairs. Do not reset, commit, publish, or install into the user's active repositories. Maximum five audit rounds. Temporary fixture repositories and package extraction are allowed validation targets.

## Exit criteria (fixed before iteration)

1. No unresolved P0/P1/P2 correctness, safety, workflow or compatibility defects. Any non-blocking deferred issue must name impact, evidence and rationale; it must not be disguised as a passing test.
2. Regression, real Git hook, install/doctor/uninstall, report freshness and packaged-artifact checks pass for the available environment. JSON/JS/shell syntax and whitespace checks pass.
3. Agent, four skills, shared contract, CLI, templates, manifests and README agree on requirements, states, failure routing and supported capabilities.
4. Two consecutive review rounds find no new substantive defects; final verification applies to the latest code. Cosmetic preferences alone do not reset this counter.
5. Platform/host tests unavailable locally are explicitly reported and cannot be claimed passed. An unavailable optional host integration is a disclosed limitation, not an excuse to ignore reproducible local defects.

Early exit requires all criteria above; otherwise stop after round 5 with an explicit outstanding-issue ledger. No round is declared clean merely because the existing tests pass.

## Method

Each round records scope, concrete findings, regression reproductions, repairs, checks and remaining issues. Read-only independent reviews supplement direct source inspection. Add behavior-level tests before fixes. Broaden or repeat verification only after changes or new evidence justify it.

## Planned rounds

1. Runtime boundaries: Markdown/index/commit parsing, evidence gate and installation lifecycle; independent reviewers inspect actual source.
2. Integration boundaries: package extraction and installed CLI, plugin manifests/adapters, malformed reports and workflow consistency; recheck round 1 fixes.
3. Adversarial follow-up: affected paths, recovery/rollback and review of current changes; may be first clean round.
4. Confirmatory independent review and latest-code verification; early exit if second clean round.
5. Reserved for unresolved findings; no automatic fifth round if early-exit criteria are met.
