# Flow-control audit and repair

Scope: all six skills, primary agent, shared contract, native capability handoffs, report templates, CLI route/ready, installer and host registration. Maximum three rounds; exit when native roles are explicit, artifact/report responsibilities are separate, known bypasses have regression coverage, independent pressure/code review has no unresolved substantive findings, and full regression plus actual package installation passes. Live host invocation is a separate environment limitation.

Round 1 baseline: planning-report substitutes writing-plans and has no actual plan reference; implementation executor is unspecified; quality review is incorrectly a spec-review prerequisite; final verification can skip Superpowers. Machine gate accepts task-ID-only mappings and no invocation/plan. Existing proposal-only stop and archive authorization boundaries pass pressure tests. Host skill registration has no missing entries.

Design: delegate writing-plans to create its actual Markdown plan; preserve native path preference and stable OpenSpec IDs. Bridge stores plan path/byte SHA-256, invocation receipts and mapping, never a replacement plan. Route and ready verify a contained regular plan file directly (including ignored files) and its hash, required invocation roles, and meaningful task mapping. Task reports bind executor/TDD where applicable and independent code-review receipts; final reports bind actual verification and final review, plus native OpenSpec verify entry. Receipts are structurally validated Agent assertions, not authenticity proofs.

Execution order: native proposal -> effective context -> native writing-plans -> native executor -> Bridge spec review -> native code review -> combined task PASS; final native review + native verification + OpenSpec verify -> ready -> authorized archive. Finishing a development branch does not grant commit/push/merge authority or bypass final verification. A single-stage request stops at its endpoint.

Plan: (1) reproduce failures before runtime changes; (2) implement receipt/artifact and mapping checks with focused regressions; (3) adapt all skills/templates/agent and recovery docs; (4) re-test pressure scenarios and independently review runtime; (5) full tests, package integration, syntax/diff checks and audit evidence. No version bump, commit, push or global installation requested.

## Results and exit decision

Round 1 repairs: PLANNING delegates actual writing-plans and retains the real plan; explicit native executor/TDD/review/final-verification roles; spec review precedes quality review; finishing and single-stage authorization stay inside Bridge routing. Machine gate rejects absent/legacy invocation receipts, absent/changed/non-contained plan files, and ID-only mappings. Four targeted red tests demonstrated the missing checks before the corresponding implementation.

Round 2: six workflow pressure scenarios passed; two wording inconsistencies repaired (reuse existing archive authorization and distinguish Markdown report summaries from the actual plan). Independent gate review found ignored context/planning reports absent from workspace fingerprint. A fifth red regression reproduced acceptance of stale final evidence. Fingerprints now force all active context/planning reports into their input set regardless of Git ignore. Regression also covers changing the ignored real plan and updating its declared hash while attempting to reuse final evidence. Final reviews explicitly include HEAD and uncommitted/untracked changes.

Round 3: independent contract and gate reviewers confirmed no new substantive P1/P2 in scope. Known scenarios now fail safely: plan missing/changed; ignored reports/plan; wrong/unexecuted Skill receipt; missing executor/TDD/review/verification; non-behavior tasks without explicit exemption; native source/report masquerading as plan. Existing exploration/proposal single-stage stopping and authorized archive remain intact. Discovery manifests and installed runtime include all required resources.

Final actual command: BRIDGE_PACKAGE_TGZ=<new tarball> node --test --test-reporter=spec tests/bridge.test.mjs tests/audit.test.mjs tests/workflow.test.mjs. Result: 74 tests, 73 PASS, 0 FAIL, 1 explicit POSIX-only permission skip on Windows. File symlink test did run under this test environment's permissions. Real tarball extraction/install/doctor/route/spec-fingerprint/plan-fingerprint/OpenCode registration passed. JS/shell syntax, JSON parsing, default-BLOCKED templates and git diff whitespace checks passed.

Exit criteria satisfied after three rounds. No version bump, commit, push or global skill installation performed. Host invocation receipts are structurally checked assertions and do not prove genuine execution; real business-host end-to-end invocation remains untested. Old reports without the new plan/delegation/mapping fields must be genuinely regenerated, not stamped. Only native capabilities and explicit project/user authorization determine execution and archive permission.
